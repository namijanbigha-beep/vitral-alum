# گزارش پایان فاز ۳ — ارسال، صادرات، پول

تاریخ: ۱۴۰۵/۰۷/۱۳ (2026-10-05)

دامنه طبق بخش ۲۰: ماژول ۷ (بسته‌بندی، ارسال داخلی، صادرات)، ماژول ۸ (حساب‌ها، سه ارز، هزینه، ثبت آزاد)، فاکتور و برگشت از فروش، اسناد صادراتی، سفارش ساخت قالب شش‌مرحله‌ای، ورود داده برنامه‌های قبلی.

## چه چیزی آزمون نشده

- یک محموله صادراتی از ثبت تا گذرگاه و فاکتور تجاری، که شرط دروازه است، آزمون خودکار ندارد؛ فقط تکه‌ها جدا آزمون شده‌اند.
- ورود فایل واقعی برنامه فاکتور قبلی و خروجی ChatGPT؛ فقط با نمونه ساختگی.

## تصمیم‌های من در جاهای ساکت سند (قابل تغییر)

1. D5: فروش هنگام صدور فاکتور شناسایی می‌شود؛ مالیات ارزش افزوده فقط اگر ردیف نرخ مالیات داشته باشد؛ تنظیم سراسری مالیات وجود ندارد.
2. D7: نرخ ارز دستی و با متن منبع ثبت می‌شود (`finance.post`)؛ در تخصیص بین دو ارز نرخ توافقی همان لحظه ذخیره می‌شود.
3. دریافت فقط به فاکتور و پرداخت فقط به خرید، اجرت یا هزینه تخصیص می‌یابد؛ طرف‌حساب هر دو سند باید یکی باشد. پیش‌پرداخت به سفارش هم تخصیص می‌گیرد.
4. کارمند سند از نوع هزینه نمی‌سازد؛ دریافت و پرداختی که کارمند ثبت کند تا تأیید مالی در مانده اثر ندارد.
5. در ورود JSON قدیمی، پرداخت‌ها و حرکت شمش وارد نمی‌شوند چون مبنای دوباره‌شماری ندارند؛ فاکتورها برای بررسی دستی یادداشت آزاد می‌شوند.

## محدودیت‌ها

- سفارش قالب صفحه رابط ندارد؛ فقط از API.
- مرحله «تست» سفارش قالب فیلر پیشنهادی نمی‌سازد.
- ورود فایل JSON یا اکسل از رابط ممکن نیست (نوع فایل مجاز نیست).
- لینک مهمان برای یک سند یا گالری بندیل فقط از API ساخته می‌شود.
- حواله ارسال به رنگ یک‌مرحله‌ای است و «در مسیر» نمی‌ماند.

## چطور امتحان کنم

1. «مالی ← جدید»: نوع دریافت، طرف، مبلغ، ارز، «قطعی کن» (با مجوز مالی)، «ثبت».
2. در سفارش تأییدشده‌ای که قبض باسکول «فروش» تأییدشده دارد: «صدور فاکتور».
3. در جزئیات دریافت قطعی، بخش تخصیص: «به سند باز» را انتخاب، مبلغ، «تخصیص».
4. «حواله ← جدید» با «صادراتی» در کارت «حمل»؛ «ریز بسته‌بندی»؛ «ارسال (حرکت بار)»؛ «رسید به گذرگاه».
5. سفارش قالب: `POST /api/v1/die-orders` و سپس `/api/v1/die-orders/:id/advance`.
